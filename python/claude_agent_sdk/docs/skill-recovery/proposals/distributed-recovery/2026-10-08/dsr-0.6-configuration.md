### Certificates, encryption, keys and readers

The approved certificate hierarchy uses a protected root CA and scoped intermediate CAs where role/environment separation needs them. Keep root and intermediate private keys outside all job containers. Each trusted service has a distinct leaf identity and private key. Validate the full configured chain, validity, intended DNS/service name and key usage; never disable verification. Map authenticated identity to the admitted role and client/job/lineage/resource/action policy before retrieval or effects. A new certificate or renewal does not expand permissions. Rotation, revocation, certificate lifetime and denial tests must be captured with the admitted configuration before protected execution. Store credential references separately from recovery objects; never archive private keys or ambient credentials in a workspace checkpoint.

AES-256-GCM encrypts checkpoint contents outside Workflow code, with a 256-bit key, a unique 96-bit nonce per key and a 128-bit authentication tag. Canonical associated data binds scope, object identity and schema. Persist the exact authenticated envelope and both plaintext and stored-byte digests. Failed authentication releases no plaintext. The separate key broker owns scoped key references and release policy. It must preserve decryptability through all retained references and must not release issuer, administration or raw root keys to jobs. The trusted materializer may receive only the admitted recovery key or authorized decrypted bytes needed for that job.

The approved human decision algorithm is Ed25519. The Python gateway holds signing authority through the separate broker and controls approval, answer and resume Updates. Minimum token version is 1 for the new governed profile; validators reject missing/stale versions and preserve the canonical exact payload binding, expiry, nonce and lineage rules. Public verification keys and key IDs are admitted run inputs; old referenced verification keys remain available through replay/retention. Gateway retry preserves the original decision identity and payload. Pending decisions wait to their existing deadlines while the gateway is unavailable and then follow the canonical no-answer result. Neither a signature nor a client certificate bypasses policy.

## Ordering and failure contract

The [ordered integration boundaries](dsr-0.6-preparation.md#ordered-acceptance-boundaries) remain required. A sealed manifest binds exact opaque conversation/pending records, workspace metadata and preimage/postimage, original call key/ordinal, predecessor, package/policy/runtime and source execution identity. Application acceptance determines the current head; uploaded latest objects do not. No atomic transaction across Temporal and S3 is claimed. Admission and publication/reply loss must reconcile the same logical identity, not create another operation.

An effect may succeed before result/postimage publication. If no definitive matching result and required postimage survive, park the original pending call. Restoring pre-effect files and rerunning Bash to recover output is forbidden. Accepted state missing from storage is a durability qualification failure even when refusal preserves safety. Host termination prevents future code in that instance; it does not undo an accepted external request or prove its outcome.

Planned destructive cleanup must preserve required sole-readable bytes before termination; refuse routine cleanup while required sealing/publication is unresolved. When urgent containment requires destruction, keep the unresolved effect parked and record any lost required data rather than claiming recovery. Genuine permanent loss cannot be repaired by pretending a postimage can be captured after death. Independent accepted state already stored outside the guest remains the recovery boundary.

Do not archive credentials, sockets, host mounts, device nodes or proc/sys/dev. Reject traversal, escaping links and unsupported metadata before SDK startup. Preserve hidden files, deletions, executable bits and admitted links/ownership metadata. Reinject approved secret references separately. Authenticated integrity and decryption key survival are mandatory; encryption does not prove freshness. Exact bundle encoding and envelope encryption remain proposed implementation choices, to be reconciled with the existing conformance contract before implementation.

Block effect access to instance metadata credentials, host/provider/Temporal administrative credentials and runtime sockets. Default deny egress, then explicitly admit required destinations without offering a complete capability-fencing guarantee. Synthetic credential markers and policy negatives qualify the boundary without inspecting live credentials.

## Evidence and prior art reuse

Existing research supplies fit, source pins, rejected alternatives and maturity limits. Fresh lead grounding on October 11: one successful Temporal Docs call on independent Entity scheduling, Update/reset/retention and Activity cancellation; one successful Atlas wrapper query on the same authority pattern; installed Temporal developer guidance applied for deterministic orchestration versus Activity I/O. Entity state ownership is partial precedent, not a sanctioned full arbitrary-Bash recovery protocol. No complete original-pending plus immutable workspace plus independently terminated two-host runtime was qualified or found in this bounded search.

Fresh public AWS documentation reads check only the selected service primitives. [S3 conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) apply to the current version and can succeed after a delete marker; protect object lifecycle and exact version identities. [S3 versioning](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html) retains versions but permits deletion and versioning suspension by authorized actors. [S3 service model](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html) supplies object consistency, not a multiobject application transaction. [EC2 termination](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/terminating-instances.html) makes an instance unrestartable and warns that other launch mechanisms may replace it. [Stop/start](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/how-ec2-instance-stop-start-works.html) remains an alternative, not equivalent evidence. These mutable source observations are not installed runtime pins.

Temporal grounding: [Entity pattern](https://docs.temporal.io/design-patterns/entity-workflow#implementation) for state/handler/Continue-As-New precedent; [Activity cancellation](https://docs.temporal.io/activity-execution#cancellation) for cooperative cancellation limits.
