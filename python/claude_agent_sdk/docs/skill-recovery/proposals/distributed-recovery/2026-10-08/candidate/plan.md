## Architecture

New Workflow state coordinates bounded accepted receipts, exact pending call identity, decisions, parked effects and logical lineages. Stable WorkflowId names the logical session; Worker/host replacement normally replays the same RunId. Continue-As-New is deliberate bounded handover with new RunId, while reset/retry are separate operations. Open conflict/closed reuse policies are configured explicitly; closed uniqueness is retention bounded. Keep independent runtime/engine/attempt identities. Proposed segment/effect/lifecycle queues are roles, not discovered deployment topology. File/provider/runtime/database IO runs in ordinary Activities through the existing seams. _workflow policy call currently fails closed with PolicyExecutorUnavailable; preserve that gate until a supported executor is registered and tested. Do not bypass it using a separate agent loop (EV-32/EV-37/EV-40).

Recommended comparison target: exact immutable trajectory blobs and cold workspace bundles, one immutable manifest binding every component, and a bounded accepted head/receipt in Temporal. Accepted Activity completion/messages make the head durable; Query readback does not store it. Materialize through the existing SessionStore append/load/conditional append/readback/head guard, including exact UUID/type/original pending identity. Compare bounded exact transcript delta history and transactional SessionStore without imposing a separate database. Storage ACK and readback precede manifest acceptance; orphans dispatch nothing, accepted missing bytes refuse rather than invent state. Continue-As-New must retain/reanchor every live/resettable blob reference, not merely pass expired old keys (EV-32/EV-35/EV-38/EV-41).

Add protected independently durable dispatch authority before Bash file claims/spawn. Prefer qualifying a separately started retained Entity Workflow owning the one existing effect Activity scheduling decision with maximum_attempts=1. Duplicate Update/request returns status or recorded outcome, never a reusable permission for caller spawn. Compare a unique transactional SQL/equivalent admission authority and downstream enforced idempotency where the effect service supports it. Stable original logical lineage/ordinal/key/input digest excludes current RunId/attempt and survives outer reset/handover. Authority reset/recreation/deletion/expiry is forbidden throughout recoverable windows and tested with actual administrative permissions; Continue-As-New carries dedup/claims/tombstones. Retain protected wrapper/file claims and no redo/release until qualified. Arbitrary Bash still parks after postintent uncertainty, even if spawn did not occur. Missing/regressed authority refuses, never reconstructs empty (EV-34/EV-39).

Cold restore preserves canonical admitted cwd, hidden files/deletions and required metadata, validates the complete immutable manifest and admits no escaping archive member/link or protected writable alias. Durable reattachment proves actual mounted backend claims/flush/visibility and admitted receipt. Canonical v1 shared-volume authority stays unchanged until BD-6 adoption; cold bundle protocols are this candidate's proposed extension. VM memory/clone snapshots are optional acceleration, not application acceptance or old host termination. Temporal Service regional disaster recovery/forced failover is a separate optional failure domain, not covered by placing Workers on two hosts (EV-33).

Supervisor adapters reuse existing controller/lifecycle contract against maintained substrate. Terminal evidence is checked before effect or replacement dispatch, independent of heartbeat timeout. Effects get only necessary package read only and work/ writable. Gateway/codec/retention require later integration and proof. EV-11 describes caller validation boundaries; EV-10 supplies Python roles; four reports supply competing platform/test requirements.

Optional native lanes may project an authoritative accepted native result, but may not call $.tool.call to recreate its original ID, use process-local ref across replacement, settle deny as a pending suspension or launch effects before accepted segment commit. Full typed JSON/native record/model-visible blocks/postimages and actual pending adapter prove equivalence; suspension and mapping are distinct. Synchronous hook-to-effect Activity is rejected as a drop-in route. Required hook absence/failure at any later authority transition must refuse/park through an independent controller/capability boundary; another Mod cannot be the sole backstop. Cover native calls plus direct process/fs/http/MCP effects and plugin-origin/child bypasses. Observation-only loss may reduce telemetry while independently safe baseline continues.

Exploratory escrow separately gates model capabilities: turn.step exposes incomplete request knobs and actual streamed output, not lossless provider/trajectory data. Final return rewriting does not change emitted engine output; partial transformed chunks stand on failure. Ordinary next twice makes two requests; catch replay is dispatch-local. A selected escrow promise requires independent provider-call prevention at accepted-response recovery/next-request transitions, complete capture and raw compatible prefix; an optional observer does not require a new model gate. Existing ambiguity still prohibits unsafe model continuation (A-74, EV-19/EV-25/EV-26/EV-27).
