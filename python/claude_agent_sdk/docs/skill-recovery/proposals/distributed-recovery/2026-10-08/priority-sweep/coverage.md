## External storage: solution boundary

Temporal External Storage is an existing payload offload feature with Python support, not a missing invention. The issue's 40-result benchmark is attributed historical evidence. It does not supply a Claude conditional-append SessionStore, snapshot a workspace or retain rollback-independent effect authority. A conversation intentionally represented as accepted Activity payloads can use offload; a transcript left only in a CLI file cannot be rescued by configuring a converter.

The candidate recipe is feasible to test: accepted Temporal head, immutable exact trajectory/workspace objects, qualified original-pending SessionStore materializer, independent effect authority and independent old-execution termination. A transactional shared conversation store is an alternative. No chosen backing store or complete cross-host composition has passed here. DSR-0.11 owns store/retention choice, DSR-2.7 owns payload offload lifecycle, DSR-5.4 owns exact conversation conformance and DSR-4.3 owns host replacement.

Required offload proof includes identical converter/driver configuration on all clients and Workers, encoded bytes and reference metadata exposure, threshold boundaries, driver identity across upgrade, missing/corrupt objects, upload/retrieve errors, replay/reset retention and garbage collection. A completion upload can fail after an effect; automatic Activity retry must not repeat that effect. Use a physical counter and lost-result test, not a payload-only happy path. Uncertain shell work parks.

[Docker cloud sbx volume](https://docs.docker.com/reference/cli/sbx/volume/) snapshots on exit rather than continuously syncing, and concurrent exits overwrite the volume. It is a provider-specific cold publication lane unless a tested explicit checkpoint guarantees durable bytes before acceptance. Local Docker bind mounts, cloud sbx volumes, microVM memory snapshots and provider durable storage are separate products/contracts. A filesystem fsync inside a sandbox is not evidence of provider snapshot completion. Quiescence, snapshot receipt and crash-before-exit tests are required. Confidential attestation does not prove state freshness or termination.
