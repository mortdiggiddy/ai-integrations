Status: independent research complete, 2026-10-08. Proposed integration recipes and qualification tests only. No runtime experiment, acquisition, installation, provisioning, image operation, credential inspection, external contact or candidate edit occurred. This report owns only `storage-loop/substrate/`; other agents own other lanes.

## Answer

The available technologies can supply the workspace part of durable Skill execution. A container, microVM or confidential guest is an execution boundary; the backing storage, checkpoint publication and ownership protocol determine its durability. Use Temporal for accepted checkpoint references and sequencing, and separately durable storage for workspace bytes. Do not require VM memory restoration to preserve a conversation. Preserve the existing original pending SDK recovery adapter and cold start it against a verified accepted checkpoint.

Two concrete recipes are credible: reattach a durable filesystem, or restore an immutable workspace bundle into a fresh guest. Recommend adding the second as a first class candidate instead of making shared POSIX storage a universal assumption. This reduces storage coupling when a package needs only an ordinary local workspace at segment boundaries. It does not eliminate independently durable dispatch admission, uncertain Bash parking, or old execution termination.

## Recommended cold restore recipe

The recipe is a proposed specialization of the existing runner/supervisor and accepted commit seam, not another executor.

1. Provision a fresh qualified segment guest with a unique incarnation identity and a canonical absolute workspace path. Materialize the admitted immutable package separately read only. Restore only the workspace bundle referenced by the accepted checkpoint. Start no SDK/model/effect until restore validation and ownership admission pass.
2. Use the retained original pending adapter against the accepted exact trajectory. Disable direct native effects as today. At a segment boundary, defer the original effect/question and drain session mutations and workspace writers. Acquire the existing authoritative termination evidence; a live mutable suffix is not accepted storage.
3. Produce immutable trajectory and workspace objects, then a single immutable checkpoint manifest binding namespace, session lineage, accepted predecessor, generation, original pending call identity, package/policy/engine/image identities and all component digests. Complete uploads, durable acknowledgements and verification before returning its reference. A lost upload acknowledgement is reconciled against the same object and digest; never mint a new generation to disguise uncertainty.
4. Accept that exact manifest reference through the Workflow's recorded segment result. Object publication before history acceptance creates an orphan, which cannot dispatch effects. History acceptance before a subsequently unavailable component yields a park, not reconstruction of guessed state. There is no distributed transaction between object storage and Temporal; immutability plus explicit acceptance handles the gap.
5. A separately isolated effect guest materializes the accepted workspace. The existing trusted effect wrapper obtains durable dispatch admission outside restorable workspace before any arbitrary Bash spawn. Its one attempt policy and unknown result parking remain. Definitive result persistence and a new immutable posteffect workspace receipt are bound to the original effect ordinal. The lead's effect lane determines precise ledger semantics.
6. Require original effect guest termination before replacement admission. Restore the accepted posteffect workspace and exact recorded result in a fresh segment guest, recovering the original pending invocation. Missing posteffect receipt when execution might have occurred is uncertainty; rerunning Bash to regenerate a file is forbidden.

Upload temporary objects can be collected only once retention policy proves them orphaned and they are not referenced by accepted, pending, parked or resettable state. Claimed dispatch records are never collected by restoring or deleting a workspace bundle. S3 conditional create sees the current object version; a delete marker can permit recreation, so preserve authority with deletion permissions/retention and exact version identity rather than pretending conditional create prevents every rollback. Application content hashes are independent of ETags.

This recipe permits replacement on another host after admitted termination and independently persisted storage survives. It preserves the last accepted checkpoint, not every transient token, open PTY, active socket, background daemon or in-memory state. A long running daemon/database requiring live memory or transaction recovery is outside this initial portable workspace contract unless separately declared and qualified.

## Durable reattachment recipe

Keep the inherited sequential Docker Cloud volume candidate and self hosted CephFS/Kata candidate as alternatives. The segment/effect guest mounts the same durable workspace identity at the canonical path with distinct restricted credentials. Verify identity, permissions and accepted generation before SDK startup. For exclusive storage, delete/release the old sandbox before reattachment. For shared storage, serialized Workflow orchestration is not sufficient by itself to reject a stale guest or another execution targeting the same lineage.

Use a quiescent checkpoint boundary and a backend durable acknowledgement. An append returning, the filesystem page cache, snapshot creation starting, a Kubernetes VolumeAttachment disappearing or an object listing does not establish this application's accepted persisted checkpoint. Snapshot the underlying volume only at a declared consistency boundary; serialize its immutable identity with the trajectory receipt. A live arbitrary filesystem snapshot can capture mixed updates unless the filesystem/application contract supplies the missing consistency.

The reattachment route better serves large workspaces and live POSIX requirements, but storage client cache, mount aliases, atomic claims, permissions, eviction and restore rollback remain obligations. The immutable bundle route is easier to isolate from workspace rollback, but extraction latency, workspace size and metadata fidelity must be measured. Recommend testing both protocols first with scripted SDK inputs, then selecting a deployment based on measured needs rather than assuming microVMs imply one storage choice.

## Filesystem preservation contract

Inventory ordinary files and directories, content digests, executable/mode bits, ownership policy, symlink targets, hard link relationships, relevant extended attributes/ACLs and root path identity. Retain `.git` or other hidden state when required by the admitted package. Preserve absence/deletion as part of the resulting tree, rather than applying a partial overlay that resurrects deleted files. Verify exact admitted read roots after restore.

Do not blindly archive host paths, proc/sys/dev, sockets, host mounts, credentials, provider tokens, service account material or supervisor sockets. Declare external mounts separately; they are not silently covered by a cwd archive. Reject path traversal, links escaping the restore root, unexpected device nodes, writable aliases of protected package/state and unsupported ownership metadata before SDK launch. Preserve secret references and reinject authorized replacements, rather than copying live memory credentials. Encrypted bundles need authenticated integrity, retained decryption keys and freshness relative to the accepted independent authority. No archive format is adopted by this report; implement format and metadata conformance inside the existing preparation/supervisor path only after authorization.

## Failure tiers and takeover

Container death with a surviving host can reuse an independently retained host volume after confirmed descendant death. Pod/guest death can reuse durable CSI or managed storage after the actual runtime release. Host destruction requires durable bytes outside that host; intact host-local disks that cannot be reached are not a usable recovery authority.

An unreachable host is different from a destroyed host. Kubernetes explicitly requires verifying shutdown/power off before applying its out-of-service recovery mechanism. Its forced volume detach on timeout can act while a workload still runs and risk corruption. Therefore absence of heartbeats, Pod deletion, attachment changes and elapsed TTL do not satisfy the existing termination requirement. Obtain independent power/provider termination evidence, or retain a park until it exists. Even effective storage revocation alone leaves a possible stale network actor. Temporal Docs confirms heartbeat/cancellation coordination is cooperative and may be ignored; Activity timeout is not a kernel kill.

For a confidential guest on a malicious host, attestation verifies a chosen measured environment and release policy; it does not make stored ciphertext fresh or prevent an old guest holding previously released keys from operating. Keep this as optional BD-5 qualification. Do not use confidential image storage as persistent antirollback evidence.

## Concrete falsifiable substrate tests

These are new proposed tests, not executed evidence. Use existing runner/controller/supervisor/probe with scripted model messages and an independent witness. Record exact backend/version/region/runtime/image identities. Full host destruction and actual infrastructure fencing require separately authorized rigs. Stop on failed cleanup and retain all uncertain records.

| Test | Injection and oracle |
| --- | --- |
| S-01 container replacement | Write known work tree and trajectory, accept checkpoint, kill/delete guest, restore on same host. Require exact call/result/tree metadata, zero effects before acceptance and no surviving witness. |
| S-02 real host loss | Persist and accept checkpoint to independently located store, destroy execution host and its local disk, restore to a second host. Exact acknowledged state must survive. A mocked unavailable host is not this test. |
| S-03 reachable partition | Disconnect control plane while old guest emits an independent canary. New host must refuse SDK/effect startup until recorded real termination. Timeout or attachment release alone must fail this negative. |
| S-04 publication gaps | Fail before object completion, after durable completion but before history acceptance, and after acceptance with object missing. Orphans yield zero effects; missing accepted bytes park. No fabricated checkpoint. |
| S-05 consistency | Attempt snapshot/archive while an external writer changes multiple files, including hidden files and rename/delete. Mixed bundle must fail publication or readback validation. Quiescent exact tree is positive. |
| S-06 rollback independence | Restore work and session to an older valid bundle while independent dispatch intent retains a newer uncertain ordinal. No rerun occurs. Restore/delete a claim object or delete marker and require refusal. |
| S-07 metadata escape | Restore symlink traversal, hard links, privileged device, ownership drift, writable protected alias, missing hidden file and unexpected external mount. Each refuses before SDK. Valid executable/symlink/metadata cases remain usable. |
| S-08 volume concurrency | Race two actual hosts/guests on selected backend; test protected create/flush/readback through actual mount path. No two accepted owners/spawns. Ordinary local FS mocks do not qualify FUSE, CSI or network semantics. |
| S-09 confidential freshness | Optional: replay old authenticated ciphertext and old guest keys after newer accepted checkpoint. Reject stale state and stale execution. Successful decryption alone cannot pass. |

## Recommended candidate changes

Crosschallenge of the Temporal lane: an accepted Workflow head plus immutable encrypted trajectory blob is a sound proposed control/storage split, provided the checkpoint manifest also binds the exact workspace state expected by the pending native invocation. Encryption authenticates bytes only when an authenticated scheme is used; it does not establish freshness relative to the accepted independent head. The canonical cwd requirement here preserves this candidate's current adapter/mount contract, rather than asserting that every CLI or SDK version requires the same absolute path. A different root can be admitted only after the selected original pending recovery and native tool semantics prove it compatible.

Add S-10 native Write/Edit restoration conformance: record exact original input/result, preserve the original preimage and admitted path identity, restore hidden files, mode bits, links and relevant metadata, then exercise actual native Write/Edit on the recovered pending path. Repeated Edit must not apply a patch twice, and a Write result must not hide a missing postimage. Fake transport demonstrates protocol ordering, exact JSON admission and intended refusal only; it cannot prove real native bookkeeping, SDK callbacks, provider behavior, filesystem durability or host shutdown. Capture the same current original recovery route and version identities in the actual native test, rather than a generic conversation resume.

Unknown Bash requires special care: a fresh workspace snapshot after possible execution cannot convert uncertainty into a successful result or erase independent dispatch intent. It may be retained as an investigative artifact, but it is not admitted posteffect state for continuation until the original definitive result and required cleanup are established. Snapshotting all state to a matching older point must still refuse if the independent accepted head or dispatch authority says a newer ordinal might have executed. Never use a tidy restored directory as an oracle that an external action did not occur.

Expand INV-2/INV-5 and M2 to permit either qualified durable reattachment or immutable cold workspace restore at the identical canonical cwd. Keep shared protected file claims as one deployment specialization, rather than universal storage choice. Introduce a portable workspace manifest interface and immutable component publication/acceptance gap tests. Preserve the independent dispatch record outside rollback and exact original pending recovery. Distinguish host destroyed from host unreachable in INV-1 and A-64 tests. Reference actual Kubernetes non-graceful shutdown constraints as existing operational precedent, not a custom theory. Leave BD-2 owners/platform and BD-5 threat model decisions open, while making concrete default recommendations for cold recovery and partition parking.

No ticket acceptance is closed by this report. A useful next preparation is a scripted checkpoint/restore test vector specifying tree metadata, accepted trajectory and two publication crash gaps. It can be authored without live models or infrastructure; actual implementation/execution and substrate provisioning still require their respective authorizations.
