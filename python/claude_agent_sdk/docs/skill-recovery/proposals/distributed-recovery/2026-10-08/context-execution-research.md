## Answer to the execution question

A Temporal Activity can own the invocation of a local restricted processor or a remote execution service. A Child Workflow can coordinate provision, restore, execute, reconcile, checkpoint and teardown stages. A Workflow is not a replacement operating system: arbitrary filesystem, network and process operations still execute in an Activity or an external service. See S-01 and S-02.

One Activity around `ctx_execute` records one outer operation. It does not identify every write or request inside the generated script. If the script changes an external system and its result is lost, retry can repeat that change. An Activity retry policy of one prevents automatic retry of that Activity; it does not prove whether its first execution started, completed or remains alive. Cancellation is cooperative. See S-01 and S-03.

There are two different execution designs to compare. An unrestricted script is one effect with an ambiguous outcome boundary. A restricted interpreter can suspend at each approved host function, so the coordinator can record and dispatch each effect separately. The second design has concrete prior art in the inspected harness. It still needs qualification under the original Claude SDK pending call contract.

## Context Mode findings

The useful separation is between complete artifacts and the small passages a model receives. `ctx_index` and `ctx_search` use chunking, SQLite FTS5, BM25 and trigram retrieval. This can support a derived index that is rebuilt from retained artifacts. ContentStore can recreate a corrupt database; default constructor storage and configured persistent project storage have different lifetimes. Session snapshots are not proof of an exact accepted Claude recovery record. See S-04 store and snapshot sources.

`ctx_execute` invokes ordinary language runtimes. Its implementation uses the project directory and inherits the parent environment with a denylist. Temporary script files do not confine writes or network access. The tool description about non-shell working directories does not match the inspected executor. Unix process group cleanup is useful local behavior, not independent whole execution termination. See S-04 executor source.

Background mode can leave a process running after partial output is returned. Without an explicit timeout the executor has no execution timer. A timeout with partial output can return an MCP success response with an explanatory note. The effect coordinator must not interpret that response as a completed effect or proof of nonexecution. Policy evaluation errors can allow execution through. See S-04 server source.

Generic external MCP routing provides periodic guidance rather than guaranteed interception. Browser filename routing depends on instructions and does not suppress every automatic browser response. These features can help context usage; they are not effect admission controls. The local multiwriter SQLite design does not establish distributed file claim or storage semantics. See S-04 routing and ADR sources.

## Restricted Code Mode findings

The current harness uses a Monty interpreter with explicit host functions and VFS capabilities. Pure computation still uses pooled subprocesses. The useful change is the capability and replay boundary, not elimination of processes. Workflow stepping reconstructs computation on replay with controlled time, entropy and timers; transient interpreter state is not itself a durable history checkpoint. See S-05 driver and stepper sources.

Suspended host calls pass through `runner.run_tool`. That function does not automatically make each call an Activity: registered Activity tools schedule Activities, while Workflow tools can run inline. External effects require the appropriate external execution boundary. Current test definitions check replay Activity arguments, rejected type checks before host calls, VFS operations, gathered calls and runaway computation handling. These are source evidence, not a local test pass. See S-05 tool, agent Workflow and test sources.

Current Code Mode requires the ambient `AgentWorkflowRunner`, registered tool, approval and event contracts, VFS configuration, and optional `pydantic-monty==1.0.0` dependency on every hosting Worker. No standalone Claude SDK adapter is demonstrated. Component reuse requires adapter, version and replay compatibility qualification. No dependency change is authorized by this note.

Storage still needs separate qualification. `ActivityFileSystem` defaults to three attempts; this policy must not be inherited for arbitrary ambiguous mutations. `FileIndex` records touched path metadata and reads current backing contents rather than historical bytes. The memory example uses local storage for one serving Worker and recommends shared storage for real deployments. External payload storage addresses history payload size, not model context size or the retained lifetime of every live reference. See S-05 filesystem, memory and payload sources.

## Mods findings and source freshness

The latest public generated declarations still identify CLI `2.1.277` and early access. Live documentation covers later runtime features and instructs readers to use the actual emitted types. It documents default activation from `2.1.286`, and that the old enable variable is ignored from `2.1.287`. Historical activation failure remains valid for its recorded runtime; it does not reject every later runtime. No newer runtime or version floor is selected here. See S-09 through S-11.

`tool.call` can inspect an outer MCP call, deny it, or answer it with a schema compatible result. Returning core's opaque `ref` preserves its host messages; that reference is not a portable recovery receipt. A plugin's `$.tool.call` creates another tool call identity. It must not be used to restore the original pending call. See S-09.

`session.append` offers a more precise context projection seam: it can change tool result content before transcript storage and model input. Structured result records and provenance remain outside the hook input, and the original tool call identity is pinned. This is promising for native bookkeeping, but it is not merely UI rendering. A qualified design must retain the exact original result and the exact accepted projection, with their identity and version binding. Preserve result status and determine the projection before its storing segment is accepted. Do not rewrite an accepted transcript prefix or reconstruct its result with a later search. The event does not provide arbitrary result injection or a durable commit barrier. See S-09 and S-10.

Ordinary hook failure can fall through to core. A catch handler does not cover absent or unloaded Mods. Live administration documentation says repeated hooks worker crashes can unload installed Mods, including organization guards; safe mode also omits installed guards. Native tool deny settings do not automatically constrain a Mod's own filesystem or process capabilities. Capability interception and namespace withholding are useful composition controls, but an external MCP server's subprocess is outside that API surface. Independent prevention remains required. See S-11.

No supported durable original call suspension and fresh process continuation handshake was found in the inspected reference, event, API, administration and test documents. A process resident callback waiting on its own Promise is bounded by a hook budget. Starting Temporal work in such a callback does not by itself establish accepted segment ordering. Streaming model response capture remains exploratory: emitted chunks cannot be recalled. Tool batch and agent identifiers do not establish positive child recovery or multiple pending call recovery. See S-09 through S-12 and the owning [Mods synthesis](mods-synthesis.md).

The official `claude plugin test` method supplies event stubs without a session, sign-in, model or network. It is a useful future preparation route if an approved installed runtime supports it. Stubbed tests cannot prove SDK activation, actual native mapping, host fencing or distributed recovery. An unanswered stub can skip a hook, so tests must assert callback coverage and negative effect counters rather than only a successful exit. See S-12.

## Execution alternatives

| Alternative | Benefit | Failure boundary and risk if wrong | Smallest qualification, not executed |
|---|---|---|---|
| Fixed artifact processor Activity | Smallest context processing scope; exact input artifacts and a derived index can be restored independently. | Read only intent is insufficient. Live workspace writes, network access, unbound processor versions or cross-session references can alter effects or expose data. | Use immutable input bytes, fixed processor/version/query and a stable output identity. Deny live workspace mutation, network and background descendants. Permit only bounded scratch and derived index/output writes. Delete the index and rebuild it from retained bytes on another Worker; compare artifact hashes and passages, then recover the stored accepted projection unchanged rather than replacing it with rebuilt search output. |
| Restricted Code Mode component | Makes host calls explicit and permits per-operation durable coordination. | A host function that executes effects inline, interpreter escape, or automatic retry can defeat the boundary. A new custom tool is not admitted by governed v1. | One harmless registered host function and a read only immutable mount. Check exact replay arguments, capability denial, lost completion and original Claude call/result identity. Start serially; retain one-attempt unknown handling for unsafe effects. |
| Whole `ctx_execute` effect Activity | Preserves the outer command boundary with little interpreter adaptation. | The inside of the script remains opaque. Partial output or lost completion can conceal completed or continuing effects. | One witnessed harmless mutation, lost completion and no second spawn. Unknown outcome must park with no next model segment. Disable background mode and prove complete old execution termination independently. |
| Identified remote job with submit and poll Activities | Separates execution from the Claude host; retryable reads can reconcile an existing job. | Submission can succeed before its acknowledgement is lost. Provider identifiers returned only after submission cannot prevent duplicate creation. A deduplicated job can still lose its result. | Fake provider with atomic logical operation key enforcement and lookup by that key. Drop submit and completed-result replies, then reconcile one job and recover exact retained stdout, exit code and result artifacts. Test artifact lifetime and repeated lookup. Provider capability remains an open choice. |
| Async Activity completion for that identified job | Frees the Activity Worker slot while external execution continues. | An expired task token does not stop a remote job. Retrying submission can duplicate work. | Expire completion authority after a witnessed job outcome; retry result delivery and consult the retained job identity without resubmission. Test authorization of result delivery separately. |
| Child or Entity Workflow for execution lifecycle | Gives a multiphase job a durable logical owner, status and separate history. | Workflow closure, reset, reuse, stale messages or automatic provider resume can undermine ownership. Logical closure is not process death. | Duplicate request and lost Update response; authority reset, missing authority and history handover. Require one scheduled execution or explicit refusal. Physical cleanup needs a separate witness. |

These alternatives can be combined, but composition requires its own qualification. Context Mode indexes, external payload storage and native result content projection solve three distinct problems. They must not be presented as one storage mechanism.

If an output exclusion limit is mandatory, a missing or failed projection Mod must prevent the next model request through an independent control. Falling back to the full result is permissible only when that exclusion limit is not promised. Test physical effect counts and unintended model payload exposure separately. Likewise, measure Temporal payload bytes, Worker memory and model input bytes separately; external storage can reduce the first while leaving the other two large.

An additional design option is to let a restricted processor produce an immutable draft instead of writing the live workspace, then use a separately accepted publication operation. This reduces the processor's mutation capability. It does not make escaped network requests reversible, and it requires explicit publication and checkpoint pairing semantics. It is a proposed requirement to compare, not an implemented transaction or a new executor.

## Failure envelope and contract limits

| Failure | What can be reused | What is still required |
|---|---|---|
| Surviving host, container replacement | Recorded local cleanup evidence on its qualified platform; host volume may survive. | Verified cleanup of the old execution and descendants, preserved exact bytes and claims. Timeout or container deletion alone is insufficient. |
| Permanent host and disk loss | Retained external artifacts and recorded Temporal outcomes, if already accepted and available. | Restore the exact accepted conversation/workspace pair on H2; preserve authority outside restored files. An execution queue or provider snapshot alone supplies no such guarantee. |
| Network partition | Logical authority can reject stale publications. | The old host can still mutate files or call external services. No replacement effect dispatch before independent whole execution termination under the approved direction. Reconcile or park already escaped effects. |

The inspected OpenAI exec adapter has no application operation key and can inherit retries. Its workspace persistence returns Activity payload bytes. The Go sandbox example has stable wrapper Update identifiers, but command Activities can retry; its E2B stop adapter accepts DELETE acknowledgements and supports autoresume. Neither is a qualified replacement for the current authority or cleanup contract. See S-06 and S-07.

The Pi article reports Worker interruption and stale transcript write rejection with shared files and Git bundles. It explicitly admits that old tools can still produce effects. Its unknown result permits a fresh model step, which differs from this project's mandatory ambiguous Bash parking. It is useful reference evidence with a different failure contract. See S-13.

Governed v1 excludes external MCP tools and prefixed custom effects. Context Mode tools or a script tool need explicit policy, executor and differential qualification before admission. A fixed internal processor also needs qualification if it changes the native result representation. The mandatory Claude SDK entrypoint and original pending call recovery remain in place. A lifecycle Child Workflow does not establish recovery of Claude native subagents. Positive child recovery, parallel pending calls, complete response escrow and confidential execution remain within their existing recorded limits.

## Recommendation and owner impact

First reuse the artifact/index/model-input separation as documentation principles. If optional context processing is selected, compare a fixed immutable processor and exact stored result/projection before a broader execution component. Keep the current SDK pause and recovery mechanism. Compare restricted Code Mode as a further component reference and the identified remote job recipe as the provider alternative. Do not enable unrestricted `ctx_execute`, adopt another inference loop or inherit sample retry policies.

This recommendation is research preparation, not a change to the concrete AWS configuration or adoption of a full protocol. DSR-0.6 and DSR-0.11 remain decision owners; DSR-2.1 stays blocked. The existing [six owner decision split](dsr-0.6-configuration.md) still applies. Storage survival, independent authority, isolation and authoritative termination remain applicable choices that must be settled. Optional context processing, Mods projection and controlled script tool admission can remain deferred under BD-6. If selected now, their interface and result preservation choices must be explicit before implementation. The research closes no acceptance criterion.

Optional processing and projection do not block portable work by default. The immediate decision remains selection or replacement of the proposed first portable qualification stack. Internal artifact processing and admission of a Claude visible custom tool are separate choices. If selected, define the exact raw/native fields and accepted representation, receipt/version binding, admission boundary, dependency/license route and owner in their existing authoritative documents. A new call identity, later retrieval order or rewritten accepted prefix cannot restore the original result.
