## Source identities and disagreements

The official October 1 announcement names CLI 2.1.287 or later and says the selected runtime's emitted declarations are authoritative. The supplied immutable source declares CLI 2.1.277 and early access. Public repository freshness does not resolve this difference. The announcement describes session host state through $.state; the pin declares a local persistent JSON $.store. The surfaces remain separate until an approved runtime actually emits and exercises its contract. The declaration response hash and exact excerpts are in mods-research/surface/pinned-types-excerpts.md.

The historical SDK 0.2.154 / CLI 2.1.274 probe forwarded plugin options and listed the plugin but did not observe its unique interception marker. That invocation remains rejected. This result does not reject every later Mods runtime. The selected SDK 0.2.162 / CLI 2.1.274 original pending recovery PASS remains distinct, as does the synthetic injected result DEFECT. None is upgraded or repeated by source research.

All three lanes agree that interception is useful but is not an atomic effect/outcome transaction, a remote session store or physical termination authority. The native middleware can observe, transform or replace actions, but its failure contract allows lower execution. A durable bridge must therefore qualify independent prevention and accepted state barriers, rather than equate a callback with a Temporal commit.

## Required controls and tests

The current validated package runner sets plugins=[] and excludes arbitrary plugin and bundled Skill invocation. A future trusted Mod needs separately approved, immutable admission without loosening those exclusions. Missing required bridge before startup refuses; required bridge failure after startup must park/refuse through independent controls. An optional observer may be absent without blocking safe execution, but its telemetry guarantee then does not apply.

Preserve accepted segment commit before effect, exact original pending identity, serial recovery, attempt one/fork rejection, immutable package checks, independent durable intent, protected claims, authoritative old cleanup and ambiguous Bash parking. Hook absence, throw, timeout, malformed return and catch failure must leave zero unauthorized native effects. Cover direct plugin process/filesystem/HTTP/MCP/model routes and originating hook skips; a second hook in the same failing surface does not itself demonstrate independent prevention.

Use the existing fixture/controller/supervisor/probe seams. Prepare harmless fake Messages tests for actual SDK loading, exact native mapping, stream counts, partial failure, compaction and permission ordering before any paid proof. Correlate independently witnessed physical effects with accepted history and original identities. Test model request counts separately from effect counts. Reuse the existing rollback, outcome gap and lost owner test requirements. All are proposed tests; none ran in this discovery.

## Decisions and risks

BD-1 through BD-6 remain open. BD-6 covers whether to adopt any optional Mods scope and the proposed protocol/rigor. Source research cannot choose a platform, newer installed runtime, managed policy owner or stronger accepted inference guarantee. Version qualification is an evidence gate, not permission to raise the existing floor.

If a hook is mistaken for authority, a missing or failed hook can execute a native effect outside the accepted ledger. If local state or a summary is mistaken for a portable checkpoint, a replacement can lose or mispair accepted progress. If final stream metadata is mistaken for emitted response, replay can create different tool calls. If native permission checks are assumed to cover direct plugin capabilities, a trusted Mod can escape the effect boundary. Each risk therefore appears as an explicit assumption and falsifiable milestone criterion in the revised candidate.
