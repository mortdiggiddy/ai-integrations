# Recoverable Claude Skill Execution Specification

## Status and authority

This document is the canonical specification for the skill recovery work in this fork. It defines the target contract, not shipped guarantees. [The plan](plan.md) defines the implementation sequence, [work items](work-items.md) define outstanding acceptance checks, and [evidence](evidence.md) distinguishes public documentation, source inspection, offline observations and missing runtime proof.

The historical plugin source baseline is `69f5497d3d3dec7ad3269c72ff266c2931c9f379`. Offline tool policy and harness work is recorded at `99fb461a074debfcaff6308cb0a3454b93991ed2`; the README goal clarification is recorded at `2acc081998407f9c88fdba349103f5392dab2d73`. Those checkpoints do not establish the effect executors, package validator, signed decision gateway, replacement Worker recovery or real model acceptance described below.

## Goal and scope

Run a validated Claude Code skill package, including its `SKILL.md`, resources and scripts, unmodified as a durable, governed Temporal operation. Claude owns native skill discovery, inference and invocation. This integration adds recovery, governed effects, durable human decisions and workspace preservation; it does not build another agent loop.

The end goal is a reusable integration for application authored Temporal Workflows under the required registration, security and policy contract, plus a separately verified later `temporal-agent-harness` adapter. A bounded application Workflow example must prove that contract. Arbitrary unregistered Workflows are not covered. Upstream acceptance and the later adapter are separate outcomes, not prerequisites for proving the plugin's own durable skill execution contract.

Version 1 supports only the tool set in the next section. It excludes keyed external service tools, a reserved external `idempotency_key` argument, deliberate `redo`, `release_claim`, a claims high water counter and an additional `contract_version` integer. Claim files, ordinal identity, package/policy/engine checks and explicit handling of reset risks remain required. Ambiguous Bash outcomes never become model facing `OUTCOME_UNKNOWN` results.

Non goals are token or individual model call replay, other coding engines, a general Workflow authoring framework, a sandbox product, skill specific compensation and Claude app login integration. Isolation and hosted API/provider credentials are deployment requirements, not capabilities supplied by this design.

## Supported tools and guarantees

| Class | Tools | Execution location | Required guarantee |
|---|---|---|---|
| Read | `Read`, `Grep`, `Glob`, `Skill` after package validation | Claude engine | May repeat, confined to validated readable paths; not individual durable effects. `Skill` remains denied until validated package configuration exists. |
| Repeatable effect | `Write`, ordinary `Edit` | Effect Activity | Recorded outcomes and verified content based repeatability. |
| Special effect | `Edit` whose new text contains its old text | Effect Activity, one attempt | Retains special unknown outcome handling with an explicit instruction not to repeat. |
| Claimed effect | `Bash` | Effect Activity, one attempt | Key and ordinal claims guard another spawn. Every uncertain outcome parks and prevents another segment. This is conditional on preserved claims, isolation and tested exclusive create semantics, not exactly once external execution. |
| Ask | `AskUserQuestion` | Workflow wait | One accepted signed answer per decision identity, with a deadline. |

`Agent`, background shells, todo tools, `WebFetch`, `WebSearch`, `NotebookEdit`, external MCP tools and prefixed custom effects are not offered in governed version 1. Adding a tool requires an explicit policy entry, executor and differential test. Unknown names are rejected; there is no automatic prefix admission.

## Baseline orchestration and interception

Workflow code owns the loop, immutable policy table, retained identities, outcomes, decisions and counters. Model calls, subprocesses, session storage and file operations run in Activities, never in deterministic Workflow code. Keep subprocess supervision out of Workflow modules and use appropriate sandbox import configuration. Use Workflow time and deterministic identifiers for replay relevant state.

Separate `agent`, `segment` and `effect` Task Queues isolate Workflow Tasks, engine subprocess Activities and effect Activities. Segment and effect queues have independent slot budgets; each queue requires at least two Workers. Capacity is sized from measured subprocess resource use, not historical instant model figures. A segment holds an Activity slot for the engine lifetime. Async handling must pass an event loop lag test under load.

The baseline engine defers a supported effect or question, ends the segment, and returns the paused call. No effect runs until its segment commits. The Workflow then gates and dispatches the effect, records the outcome and supplies a synthetic `tool_result` on session resume. A lost uncommitted segment may decide again with a new model call ID; no effect has run yet. Accepted request recovery must not silently regenerate a different request.

Synthetic host results remain an undocumented runtime dependency. Official defer resume describes reentering the hook and allowing engine execution, not this host supplied result path. Allowing the resumed engine to execute the effect is not an automatic fallback because it violates the external effect Activity boundary. Mixed and batched calls require real model proof through the production runner; offline observations do not establish batch safety. Reject or park unsupported patterns.

The baseline command `PreToolUse` hook uses matcher `.*`, exec form and only the standard library. It reads the same immutable validated table used by the Workflow. Before pause, confined reads receive no decision and the first supported effect or ask receives `defer`. The paused slot binds call ID, exact tool name and canonical JSON input. Identical reannouncement returns `defer` without replacing that slot. Every different call, including a read, is denied after pause; every call is denied after stop. The runner refuses a returned request that differs from the marker before checkpointing. Already answered IDs retain their inherited repeat deferral without a new slot; complete name/input binding across segments remains an unresolved proof obligation.

Effects are offered in `tools`, not `allowed_tools`. Pin `permission_mode` to `default` and install a deny only `can_use_tool` callback as the proposed preventive backstop. `AskUserQuestion` needs the selected SDK's required callback/input configuration, but that callback must not block awaiting a human inside an Activity. A post execution observation or transcript check must detect an effect executed inside the engine and park the run. Detection alone cannot prevent an effect already completed.

Prove the backstop with a hook that returns no decision, an absent output file and an observed denial. Removing the backstop must make the test fail. Also test read only Bash, permission precedence, disabled or failed hooks, batches and the selected minimum/newest engine versions. If prevention fails, the limit is detection after an unrecorded effect, not safe execution; do not claim the prevention guarantee.

Accept `extra_options` only from a reviewed, validated allowlist. Freeze nested values or validate again before use. Validate every admitted value shape and meaningful combination against locked and minimum SDK inventories. Environment, model routing, permissions, settings, plugins, agents, added directories and MCP registration are separately owned configuration. No generic raw `extra_args` passthrough is allowed; any diagnostic exception requires exact flag/value validation and engine proof. Caller options cannot override controlled permission, callback, tool, setting source or session configuration.

## Package and filesystem boundary

Preparation rejects symlinks and hashes the finished package copy from sorted relative paths, normalized modes and file bytes. The hash covers the complete `.claude/` tree, including commands. Each segment rehashes that tree and records the package hash; a mismatch parks without a model result. Only configured content hashes may execute.

The validator rejects skill shell `!` injection, skill hooks, `context: fork`, `allowed-tools` grants and unsupported frontmatter. The runner disables skill shell execution and constrains both model invocation and command dispatch to validated packages. Test hidden and bundled skills and alternate invocation paths. A startup skill inventory is diagnostic, not evidence of confinement. The Agent tool remains unavailable and background tasks remain disabled.

The baseline workspace is a shared volume mounted at one absolute deployment path on every segment and effect Worker, using a common image/toolchain. It does not depend on Worker affinity. Each run owns `<root>/<hash-of-lineage>/`, containing a Worker owned read only `.claude/` package tree and `work/`, the only effect writable area. The run directory itself is not effect writable, preventing replacement of `.claude/` by rename. The engine works from the run directory; Bash works from `work/`.

Read confinement resolves symlinks and validates `Read`, `Glob` and `Grep` paths, including `pattern`, `path`, `glob`, absolute and parent traversal forms, against the run directory and validated package paths. This controls engine reads, not Bash. Write/Edit resolve paths from the engine working directory and admit only `work/`; denied paths return `is_error`, not an infrastructure exception. Relative Bash and Write/Edit paths therefore differ, which must be tested and documented.

Preparation copies under a temporary name, renames, verifies the finished copy and writes a Worker owned manifest containing namespace, Workflow ID, lineage ID, start time, package hash and generation. Preparation is idempotent on a finished directory. Every segment verifies the manifest; the Workflow retains the last observed generation. A lower generation or invalid identity raises `ExecutorFault`, parks and returns nothing to the model.

Generation detects some restores before preparation, not every mid run snapshot rollback. A restore can lose claims or file state without lowering generation. Do not treat an unverified restored tree as safe, recreate unresolved claims empty or use `reprepare` to bypass uncertainty. A replacement storage/snapshot strategy must prove the same protected state and outcome contract before replacing the shared volume baseline. POSIX visibility, close to open consistency, user/group mapping and exclusive create across hosts remain unproven until tested on the actual volume class.

## Effect identity, execution and outcomes

The starter supplies a lineage ID carried in run input and every handover; a Workflow generated ID is a fallback only. Test first Workflow Task reset, ordinary reset and Workflow ID reuse. Reset must retain the intended lineage and consult prior claims; reused Workflow IDs must not inherit another lineage's files or claims.

Compute each effect key once from canonicalization version, lineage ID, ordinal, tool name and canonical input, then retain it with the paused call. Canonical input sorts keys, normalizes Unicode and omits volatile fields such as Bash `description`. Persist the ordinal when scheduling the effect, regardless of outcome. Activity retries and handover reuse stored identity. Use system generated Activity IDs rather than treating model IDs or Activity IDs as logical deduplication keys. Canonicalization changes require replay compatibility, not recomputation of old identities. A later model call at a new ordinal is a new identity, not safe recovery for ambiguous Bash.

Before Bash spawn, exclusively create both `ord-<ordinal>` and `<key>` claims with `O_CREAT | O_EXCL | O_NOFOLLOW` in Worker owned `<root>/.tca-claims/<hash-of-lineage>/`, outside the effect writable tree. Record run ID, ordinal, key and spawn time. Existing claims, preserved spawn heartbeat details or an attempt above one cause non retryable uncertainty and park. A missing claims directory causes `ExecutorFault`. Attempt numbers alone are insufficient because resets can return them to one. Claims prevent another spawn; they never prove completion. Different claim run IDs identify lineage history, not automatically reset versus handover.

At most one Bash spawn is conditional on retained claims, effective isolation and proven cross host exclusive create. A partitioned host, lost restored claim or surviving daemonized child remains a risk. Use one attempt for Bash, reject `run_in_background`, apply the environment allowlist and policy timeouts, wait for the entire process tree and terminate it on cancellation. An environment allowlist alone does not protect Worker credentials.

Write with identical content is a no op. Edit preserves native unique match and `replace_all` rules, records pre/post image hashes before writing and uses atomic replacement. A retry accepts the post image, applies only on the pre image and refuses neither matching. Lost heartbeat delivery must be tested. Edit whose new text contains old text uses one attempt and retains `OUTCOME_UNKNOWN` with an explicit no repeat instruction; unresolved overlapping Edit behavior blocks a repeatability claim.

Differential tests run each supported effect once natively without deferral and once through its executor, comparing the model visible result, error text and file behavior. Reproduce native Write overwrite and Edit rules; impose a native read before edit rule only if the comparison proves it exists. Infrastructure errors raise instead of masquerading as tool results.

Outcome mapping is ordered:

1. Success returns the recorded result.
2. Reserved executor `NotStarted`, established before any claim or spawn, yields `NOT_RUN`. Tool body errors cannot impersonate it.
3. `ExecutorFault`, including package/policy/engine mismatch, manifest fault or missing claims, parks with no model result.
4. The first Schedule-To-Start timeout parks every effect. Ordinary repeatable effects record `NOT_RUN`; special Edit retains its unknown handling; Bash never gets a safe no effect result from timeout alone.
5. Exhausted ordinary repeatable errors return a plain tool error.
6. Any uncertain Bash outcome, including loss, exception after claim, timeout, heartbeat timeout or unclassified post start failure, parks and blocks the next segment.

Workflow cancellation takes priority over all recorded decisions and never schedules a further segment. Tests must prove wrapper exception classification and cancellation do not become retryable failures.

### Timeouts and process lifetime

Segment defaults are 10 minute Start-To-Close, 1 hour Schedule-To-Close and 60 second Heartbeat Timeout. Heartbeat on engine output plus a 10 second timer; a configured silence watchdog kills the process tree and reports retryable failure. Rate limit/overload errors retry within the time bound; credential, quota, turn/budget cap and invalid request errors park rather than spend indefinitely.

Every effect has a 10 minute Schedule-To-Start bound. Ordinary repeatable effects use 1 minute Start-To-Close, 30 second Heartbeat Timeout and up to five attempts; special Edit uses one attempt. Bash defaults to 5 minute Start-To-Close, 60 second Heartbeat Timeout, one attempt and `WAIT_CANCELLATION_COMPLETED`. Ordinary repeatable effects use `TRY_CANCEL`. Neither cancellation mode proves the external outcome. Effect heartbeat timers remain active; effect silence timeout defaults to none because quiet commands can be legitimate.

Configure Worker graceful shutdown explicitly, install signal handling and keep deployment termination grace above the Worker shutdown timeout. Process group kill alone is insufficient for children that detach. Containment requires a control group, process tree mechanism or subreaper with the chosen isolation. A host partition remains a disclosed residual.

## Human decisions, registration and parked state

Use an authenticated gateway with deployment controlled Update credentials. Signed tokens bind Workflow ID plus lineage ID (not Run ID), purpose (`answer`, `approve`, `resume`), subject, question/park digest, decision payload digest, expiry, nonce, key ID and token version. Answer/approval subjects are minted decision IDs; resume subjects are minted park IDs. Hash canonical JSON with SHA-256 using sorted keys, UTF-8 and no insignificant whitespace, with a fixed canonicalization contract. A resume binds the stored park cause, phase and retained effect identity.

Public keys and a minimum token version are run input. Validators check signature, complete payload binding, known/minimum version, expiry using Workflow time and repeated answered identities before acceptance history. Default token expiry is the earlier of the decision deadline and 24 hours. The recent answered identity set covers every decision kind. Test forged direct frontend Updates, unsigned/expired/cross question/substituted tokens, nonce/replay attempts and resume after reset. Signature verification in the sandbox and accepted history reconstruction remain unproven.

The concrete application Workflow owns its decorator and run method. The plugin base proposes Updates `decide`, `answer_question`, `resume` and Queries `pending_decisions`, `last_effect_outcomes`, `parked_state`. Registration requires the validators, inbound token authority/interceptor and concrete Pinned configuration; a base decorator alone does not enforce it. Reject unsigned aliases, dynamic decision paths and protected handler overrides that bypass that authority. One deterministic verification authority serves the interceptor and validators. Verification after acceptance is not a substitute for validation before history; accepted handler reconstruction must still replay correctly. Historical unsigned mode needs an explicit tested migration route, not an assumed validator on every replay.

No answer Signal exists in governed mode. Compatible legacy Signal handling must drop invalid messages without stalling Workflow Tasks. Legacy `tool_policy=None` is a separate mode with no governed built in effect guarantee; the released default still needs a compatibility decision. Normal Temporal cancellation is separately authorized deployment behavior, not a signed resume action.

Questions and approvals have absolute deadlines, 24 hours by default and configurable per skill; unlimited wait is explicit. Handlers validate, record and return promptly while the main method waits. Consume an already recorded answer before declaring timeout. Reject answers at or after the deadline and return a stated no answer/denial outcome, never implicit approval. Query/Search Attribute discovery works with streaming off; alert at half the deadline. Retry gateway Updates rejected with `RESOURCE_EXHAUSTED` using the decision ID as client Update ID.

Parking retains the paused call, key, ordinal and cause, increments `park_seq`, mints a park ID and exposes `parked_state`. Causes include exhausted segment retries, credential/quota failures, contract violation, effect scheduling timeout, ambiguous Bash and `ExecutorFault`. Signed `retry`, `resume_from_checkpoint` and `abort` are proposed actions only for supported causes with tested recovery. `retry` reuses segment input; checkpoint resume reuses the last checkpoint. Ambiguous Bash recovery is unresolved: reject retry or checkpoint resume as a bypass, never clear claims, spawn again or continue the model. This does not silently select an abort only recovery policy.

Version 1 has no authenticated in flight key replacement path. Compromised signing keys require termination of affected runs. Key rotation by signed Update is not part of this contract.

## Long running execution and replay

Automatic Continue-As-New is the proposed default. Check server suggestion, estimated handover size, target Deployment Version change, wait age and periodic wake at safe boundaries. Drain handlers with `workflow.all_handlers_finished`; never hand over from a handler. Proposed defaults are 1 MiB handover threshold, 24 hour wait age, 6 hour wake interval, one wake interval cooldown and 1,000 total segments (`None` removes the cap). These are design choices to measure, not product defaults.

Human and parked waits wake using `min(wake interval, deadline-now)` with a one second floor. Preserve original `registered_at`, but reset `wait_started_in_run` at each run's wait entry. Consume accepted decisions before checking handover, retain accepted but unapplied resume actions and reenter the wait on the next run without an engine segment ending at an unanswered call. Cancellation takes precedence. Updates near handover must be visibly delivered or rejected, not promised delivered; concurrent answers accept exactly one. Deduplication must survive handover because client Update IDs alone are scoped to a run.

`AgentState` retains session ID, checkpoint, pending results, recent call IDs and counters, plus `lineage_id`, `effect_ordinal`, `canonicalization_version`, `last_effect_key`, `last_effect_digest`, `pending_decisions`, `parked_effect`, `answered_decision_ids` (bounded to 256), `park_seq`, `volume_generation`, `package_hash`, `policy_version`, `engine_version` and optional bounded stream state. Each pending decision retains kind, decision ID, paused call (ID/name/input/key/ordinal), deadline, payload, registration/run wait timestamps, park ID and accepted but unapplied signed action. `parked_effect` retains the uncertain Bash call, key, ordinal and cause, never a model result. Do not carry a whole task effect ledger or obsolete high water, claim release or unknown Bash delivery state.

Keep handover below the payload limit and trigger from measured service suggestion rather than a fixed step estimate. Cap model output at 64 KiB by default, preserve full output in the workspace and return path/digest/truncation metadata. Stage oversized Write content by workspace reference and hash; truncate stderr in failures. Test a 3 MB Write, 5 MB command output and repeated handovers. External Storage covers Temporal payloads, not conversation storage, and any preview dependency requires version pinning and compatibility proof.

Live output is off by default. When enabled, retain coarse lifecycle events only in history, move high rate output out of band or increase batching, and front viewers with one shared subscriber service. Test more than ten subscribers plus an approval; streaming must not consume all approval capacity. Record `question_needed`, `effect_started`, `effect_ended` with identity/mode, not raw input.

Pin engine, SDK, plugin and hook implementation in the Worker build and disable engine self update. Validate package/policy/engine versions before claims. Those fields do not detect every executor only change. Roll out all queues before moving runs, keep retained pinned Workers and explicitly test upgrade at handover. Resume engine N sessions on N+1 only at supported boundaries. Preserve released history fixtures and replay recent open/closed histories before changes. Workflow behavior changes require patching or a documented drain/Pinned migration route. Patch retirement uses the conservative no replayable marker bar, including retained histories that Queries or Reset may replay; its reset assumption still needs proof.

## Deployment security, lifecycle and service targets

Beyond an isolated private demo, run effects under a separate unprivileged identity or container/PID namespace with restricted `/proc`, least privilege and restricted network access. Only `work/` is effect writable. Prove no access to Worker launch credentials, package/settings writes, claim writes or surviving children. Running as the Worker user voids package/claim confinement and the conditional at most one spawn claim. The design does not supply the isolation product.

Encrypt payloads on all Clients and Workers with a Payload Codec; restrict Codec Server viewers and encode common failure attributes to protect stderr/stack traces. Test stored Update arguments/results with the actual codec. Search Attributes are nonsecret filtering metadata, never authoritative state; exclude input, output, paths and human text. Proposed attributes are `AgentPhase`, `PendingHumanInput`, `OldestPendingAt`, `PackageHash`, `PolicyVersion`, `EngineVersion`. Validate namespace registration before starting, returning a stated start error instead of stalling an upsert task.

A production session adapter is accessible to replacement Workers, encrypted at rest and deduplicates entries by UUID. Its conformance suite must cover loss, stale checkpoints, duplicate append and shared access. Select retention explicitly for compliance; seven days is only a proposed starting assumption. Every closed handover run retains its own history for the namespace window.

The external janitor uses Temporal status plus namespace and lineage identity, not modification time or a lease. Retain live, idle and parked directories. Closed `work/` and package cleanup waits for a configurable grace period; claims remain until namespace retention ends. Missing or uncertain identity, reused Workflow ID, wrong namespace and unresolved claims never authorize deletion. Termination is not a Workflow cleanup opportunity; the janitor must handle it separately.

Keep SDK and Cloud metrics in separate dashboards, with logs and traces and no identifiers in metric labels. Replay safe Workflow counters and human wait age require proof before operational claims. Record contract violations, parked uncertainty, queue delay, attempts, timeouts and lifecycle visibility without content leakage.

| Design objective | Target or alert |
|---|---|
| Segment and effect queue wait | p99 at most 5 seconds; warn at p95 above 1 second for 5 minutes; page at p99 above 30 seconds for 5 minutes. |
| Heartbeat/Start-To-Close timeouts | Zero in steady state; alert for sustained nonzero rate over 15 minutes. |
| Contract violations | Zero; any increment pages. |
| Unknown outcomes | Fewer than one per 1,000 effects; investigate sustained excess. |
| Paid retries | More than one attempt for fewer than one in 100 segments; investigate sustained excess. |
| Human wait | Notify at half the decision deadline. |
| Stream lag | Set from measured budget when streaming is enabled. |

These are project targets, not Temporal guarantees. Skill specific end to end latency is dominated by model and human time and has no universal numeric target.

## Interfaces and later adapter

Run input carries prompt, package path/hash, immutable tool policy, workspace root, segment/budget/time/output limits, decision timeouts, wake interval, Continue-As-New mode, public approval keys/minimum token version, handover thresholds/cooldown, starter lineage ID and queue names. Package loading controls setting sources, `tools`, `allowed_tools` and permission mode together, not arbitrary caller overrides.

Each policy entry has exact `name`, `class` (`read`, `effect`, `ask`), effect `mode` (`repeatable`, `claimed`), `approval` (`none`, `required`), Activity durations (`start_to_close`, `heartbeat_timeout`, `schedule_to_close`, `schedule_to_start`), optional `silence_timeout` and integer `output_cap_bytes`. `policy_version` is the canonical table digest.

Effect input carries `tool_name`, `tool_input`, `key`, `ordinal`, `cwd`, `policy_entry`, `deadline`, `package_hash`, `policy_version`, `engine_version`, `volume_generation`. Result carries `status`, `content`, `is_error`, `output_path`, `truncated`, `digest`, `volume_generation`; infrastructure failures raise. Segment results carry retained checks, generation and paused call. Proposed Activities are existing `run_claude_segment` plus `prepare_workspace`, `run_effect`, `cleanup_workspace`. Routine cleanup never releases ambiguous claims.

Keep the public API additive within the experimental `temporalio.claude_agent_sdk` plugin and follow shared repository build/test conventions. Governed mode and legacy compatibility must be distinguishable.

The later harness adapter is step level: map the segment to the receiving harness Activity boundary, streamed lifecycle output to its event vocabulary, and deferred effects/questions to its tool, approval and callback contracts. Engine reads remain internal and bypass harness policy. This is an integration proposal, not shipped compatibility. Effect ordinal/key ownership must have one agreed owner when the receiving harness owns the loop; reverify its pinned contract before that port.

## Proof obligations and unresolved choices

Completion requires real model proof and independent verification of the complete retained contract, not document agreement or offline hooks alone. [Work items](work-items.md) own executable acceptance checks and status; [evidence](evidence.md) owns proof limits. The following choices and assumptions remain open unless those documents carry corresponding evidence:

- Candidate adoption, actual SDK/Mods loading, pending request/native metadata recovery, exclusive session ownership and orphan prevention; replacement Worker tests require a Temporal rig.
- Real model synthetic result/question interpretation, permission backstop, batching and minimum/newest engine behavior.
- Workspace/volume class and actual cross host create/read visibility; snapshot state/outcome coupling and retained claims.
- Repeatable/special Edit crash and overlap behavior, executor native fidelity and exception/cancellation mapping.
- Signed gateway ownership, sandbox verification, concrete registration enforcement, historical unsigned migration and replay reconstruction.
- Reset investigation and ambiguous Bash recovery procedure; no interim procedure authorizes another spawn or model continuation.
- Deployment versioning, queue rollout, Search Attribute registration, codec behavior, retention, production session adapter and janitor ownership.
- Load/event/payload/Update budgets, process containment and operational metric behavior.
- Public contribution coordination and later harness identity ownership; neither is proof of plugin execution correctness.

Failures must remain visible: no missing checkpoint as a new session, no stale workspace as safe state, no invalid decision as approval, no version fault as a model tool error, no uncertain Bash as unfinished model work and no cleanup as claim release.
