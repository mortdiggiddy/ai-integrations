#### Context

The pinned fork passes built in tools such as Bash, Write and Edit straight to the engine. They run inside the segment Activity, are not recorded and can run again when a segment retries ([canonical specification](../canonical-documents.md#specification), Background). The design adds one tool policy table, a hook that defers effect and ask calls, and a preventive backstop that keeps effect tools out of `allowed_tools`, pins `permission_mode` to `default` and registers a deny only `can_use_tool` callback (INV-1 *Fail closed contract*, INV-3). Only an allow list of reviewed `extra_options` keys may reach the engine. The `tool_policy` option defaults to `None` and keeps today's behavior (Interfaces, *Run input*).

#### Problem

None of this exists in the fork. DSR-1.4 can prove or disprove the backstop only after the backstop is built to the rebaselined scope.

#### Scope

- The policy module: a pure function from tool name to policy entry. A name not in the table is not offered. DSR-0.2 excludes keyed effects, so a `mcp__durable__` prefix does not grant permission or expose an author tool in version 1.
- The hook policy branch: eligible read tools return no decision before a pause unless the resolved path is outside the run directory. Skill stays denied until DSR-1.5 supplies its validator. The first new effect or ask returns `defer` and claims one paused slot, bound to ID, exact name and canonical JSON inputs. An identical reannouncement returns `defer` without replacing the slot; every different call, including reads, is denied after the pause. Every call is denied after stop.
