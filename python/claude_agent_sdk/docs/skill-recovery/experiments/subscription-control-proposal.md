## Stop contract and limits

[subscription_sdk_control.py](subscription_sdk_control.py) is a single purpose proposed probe. Record and synchronously stop the owned container on the first host observed output-limit event, generated unexpected user message, unexpected tool/model, terminal error, or active/ambiguous/unverifiable overage metadata. Raw streaming events add a possible earlier `message_delta.stop_reason=max_tokens` signal; the failed invocation did not enable partial messages, so earlier detection there is unmeasured. Capture the trigger before removal and classify missing final usage as unknown, never zero. A stop is non passing even if matching text was already emitted.

The host must force-remove the named container before requesting another stdout record after a trigger. The deadline independently supervises blocked reads. The container explicitly closes the SDK generator on exit; SDK interrupt acknowledgement and graceful disconnect are not prerequisites for host removal. Removal/inspection faults remain non passing and must be reported. The reservation remains consumed on all outcomes, including timeout, incomplete logs or uncertain cleanup. No automatic retry is offered.

This is reactive containment. The CLI producer can continue before the SDK or host receives a stop event. Killing the owned container stops its local processes once Docker completes removal; it cannot retract an already accepted provider request, undo tokens already generated or prove absence of extra billing. The unchanged turn/retry/output/budget settings remain configured controls, not preventive input/total-token/currency/phase bounds. Static source inspection found no supported switch that disables the output-limit recovery branch. Do not interpret a successful new text result as prevention proof.
