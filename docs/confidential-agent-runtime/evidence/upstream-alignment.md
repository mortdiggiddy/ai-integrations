## Result

The upstream shape fits the selected division of responsibilities. Reuse the ordinary transport extension where useful. Keep the harness as the single compute lifecycle owner. Keep the native SDK, content callbacks and content policy inside the approved runtime for confidential execution. Neither PR supplies the complete confidential recovery composition.

The integration delta from the earlier inspected `2c722ff59250d3427ba5e43ea9713ecef959ee71` changes only its README and integration cancellation test. Production source, dependency metadata and lock are unchanged. The removal of the Sandbox interface was already included in that earlier inspection. The latest delta does not require another architecture change.

## Proposed upstream feedback

### Skill package loading and file placement

The [plugin sample](https://github.com/temporalio/samples-python/blob/347cff1a1efce1afdc6ead9eaf2d565a29be99ad/claude_agent_sdk_plugin/plugins/workflow.py#L14) passes `plugins=[{"type": "local", "path": PLUGIN_DIR}]` and enables the native `Skill` tool. Its [test](https://github.com/temporalio/samples-python/blob/347cff1a1efce1afdc6ead9eaf2d565a29be99ad/tests/claude_agent_sdk_plugin/plugins_test.py#L28) inspects the scripted model requests: the skill is advertised, its native tool result is returned, and the actual `SKILL.md` instructions appear in the next model request. It also replays Workflow history. This is stronger source evidence than checking a fixed final haiku alone. This review read the test; it did not execute it.

That test uses the default subprocess transport. The [sample README](https://github.com/temporalio/samples-python/blob/347cff1a1efce1afdc6ead9eaf2d565a29be99ad/claude_agent_sdk_plugin/plugins/README.md#L17) states that the plugin path is on the Worker, where the CLI runs. The inspected integration builds command arguments with the SDK and sends a launch request containing paths and arguments. The [SDK argument builder](https://github.com/anthropics/claude-agent-sdk-python/blob/v0.2.163/src/claude_agent_sdk/_internal/transport/subprocess_cli.py#L732) passes local plugins as `--plugin-dir <path>`. No general Worker to remote runtime plugin directory transfer was identified in these paths or in the Docker transport sample. `CliFiles` supplies shell scripts for process and protocol handling; that does not demonstrate plugin package transfer. Any CLI internal plugin caching is a separate operation from transfer between hosts.

Native skill loading therefore has a concrete sample and test. Automatic plugin placement into a separate runtime remains an unproved claim at these pins. A useful hardening case places the plugin only on a source host, starts the CLI on a clean remote filesystem, and checks that the same package and bundled supporting files arrive and load without a shared mount or preinstalled copy. Missing files and a mismatched package must fail before job execution. The instruction only haiku fixture does not qualify executable helpers, dependency installation or restart recovery.

For this project, a confidential skill package must reach the approved runtime through its admitted provisioning and key release path. Ordinary plaintext packaging on the outside Worker does not establish skill secrecy from that operator. Retain native plugin loading inside the runtime; bind the approved package identity to the job and restore it consistently. This is a placement and admission requirement, not a reason to recreate the native skill engine.

These comments concern the ordinary samples. Confidential requirements are not acceptance criteria for those samples.

1. Add the pending tool ID validator to the sandbox approval Update. [The Update](https://github.com/temporalio/samples-python/blob/347cff1a1efce1afdc6ead9eaf2d565a29be99ad/claude_agent_sdk_plugin/sandbox/workflow.py#L74) stores arbitrary IDs. An early decision can satisfy a later approval with that ID; unknown IDs accumulate. Reuse the sibling [human approval validator](https://github.com/temporalio/samples-python/blob/347cff1a1efce1afdc6ead9eaf2d565a29be99ad/claude_agent_sdk_plugin/human_in_the_loop/workflow.py#L74) and its unknown ID negative test. This is source supported; no exploit was executed.
2. Check permanent sandbox prerequisites before startup, or classify permanent configuration failures separately. The [command helper](https://github.com/temporalio/samples-python/blob/347cff1a1efce1afdc6ead9eaf2d565a29be99ad/claude_agent_sdk_plugin/sandbox/activities.py#L30) raises ordinary exceptions, while the selected transport default retries indefinitely. A missing `sbx` or persistent login failure should produce an actionable setup result. Transient failures still need retries and reconciliation.
3. Say "tool calls requiring permission" in the sandbox introduction and summary table. The implementation uses default permission mode; the [README explanation](https://github.com/temporalio/samples-python/blob/347cff1a1efce1afdc6ead9eaf2d565a29be99ad/claude_agent_sdk_plugin/sandbox/README.md#L5) already makes this narrower statement. Do not imply universal interception.

For integration discussion, confirm that custom transports can attach to externally owned compute and choose CLI stop independently from compute deletion. The four Activity seam already allows this. It needs no new upstream Sandbox abstraction. Lost create replies and concurrent launch attempts remain useful future fault tests; this review did not demonstrate duplicate resources on real `sbx`.

## Effect on the project

### Trusted execution deployment baseline

The inherited first deployment candidate is AWS EC2 NitroTPM attestation with AWS KMS and a mutually approved isolated Attestable AMI. The initial trust scope protects each party's assets from the other party and from unauthorized workload operator access; it does not require protection against the cloud provider. Google Confidential Space remains an alternative if a later profile needs a different platform or hardware threat model. A newly proposed Google default was not accepted and does not supersede that existing direction.

AWS documents [measured instance attestation and recipient encrypted key release](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/nitrotpm-attestation.html). Its [isolated image example](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/build-sample-ami.html) removes interactive access and uses immutable system files. The project must preserve those properties while adding the native runtime and a separately confined writable job workspace. This is NitroTPM instance attestation, not selection of Nitro Enclaves. Boot measurements and KMS conditions do not by themselves supply job authorization, generation freshness or tool isolation; those remain explicit application contracts and qualification checks. No cloud deployment or paid execution is authorized by restoring this design direction.

The specification and plan source pins now identify the latest integration. Keep the previous formal review as a dated review, and use this record for the source delta. The nine BD decisions are not closed by either upstream PR. The first contribution remains explicit external runtime placement and capability admission in the existing harness. Broader recovery and confidential activation retain their acceptance gates.
