# Native pending call and outcome recovery protocol

Status: LATER STAGE APPLICATION CONTRACT, 2026-10-26. This specifies proposed project-owned adapters for M3 and the broader service exit. It is not a prerequisite for M1. Bounded independent review supports the main-agent design and identifies the remaining active-child native capability gap. It does not describe an implemented service, qualify an SDK version or approve execution. The native SDK and CLI retain skill loading, planning, model interaction and the agent loop. This protocol supplies admission, durable effects, capture and prelaunch restoration around that loop. The specification, decision register and historical obligation map remain governing sources.

## Typed records and authorities

These names are proposed project records and operations, not SDK APIs. Confidential fields exist only inside the approved content boundary or as authenticated encrypted bytes outside it. Outside Workflow state retains opaque references, approved bounded metadata and cryptographic bindings; it does not parse tool content.

| Record | Required fields and invariants |
|---|---|
| `AgentIdentity` | Job lineage, original native session ID, agent ID or explicit main marker, parent agent identity, parent native tool-use ID, exact transcript subpath and graph version. A child ID is namespaced by its original session and graph; no global tool-ID uniqueness assumption. |
| `CallIdentity` | `AgentIdentity`, original assistant transcript UUID, native tool-use ID, tool name, canonical input digest, original authority ordinal and package/policy/profile digests. Same identity with different content is a conflict. |
| `PendingEpoch` | Original identities, exact immutable transcript heads and ordered records for every selected agent, all pending call identities, required sidecar/workspace manifest, observed writer/process closure and capture digest. Includes complete unresolved batch membership; no selecting only a convenient first call. |
| `EffectIntent` | Stable operation ID derived from original lineage/agent/call/ordinal, accepted pending-epoch reference, input digest, executor profile, generation binding and state. Protected independent Entity owns it. Runtime files cannot recreate it. |
| `OutcomeRecord` | Original call and intent identity, definitive outcome classification, exact typed raw result/error, native result projection version, complete model-visible blocks, required native carrier metadata, postimage manifest and immutable byte digests. An error result requires evidence of that actual error; uncertainty is not rendered as a tool error. |
| `ResumeManifest` | Input epoch, exact authoritative outcomes, per-agent expected old heads and deterministic append identities, output transcript heads, complete sidecar/workspace manifests, generation and capability-profile digest. All output bytes precede Session acceptance. |

The Session authority owns the selected accepted epoch/resume head. The protected Entity owns one scheduling decision per effect intent. The controller owns exact-incarnation lifecycle. The runtime supervisor validates and materializes content. Object storage preserves immutable authenticated bytes. These responsibilities do not authorize a second compute controller or a new agent loop.

Distinguish the provider compute incarnation from a native writer epoch. A writer epoch is the SDK/CLI and its admitted tool/child processes, identified by the supervisor and their confinement scope. Stopping those writers does not delete or terminate compute. The protected supervisor, capture service and effect executor can remain inside that same approved compute incarnation. They run in separate privileged service and untrusted command compartments; generated commands cannot access service keys, credentials or control sockets. A provider incarnation is terminated only for replacement or explicit controller owned removal.

The outside effect Activity sends an authenticated sealed dispatch to the inside effect executor. It handles only the accepted reference, identity, digest and permitted metadata. Tool argument validation, native projection, workspace access and content handling occur inside the approved boundary; no Worker runs there. The receiver durably consumes the original one-use dispatch identity before launching a command. Duplicate delivery returns retained status or outcome; it cannot launch again. An uncertain consumed grant stays parked. Temporal retry settings alone do not enforce this boundary.

## Stopped epoch and effect ordering

1. The trusted tool hook records the exact original call identity and returns native `defer` before a governed effect executes. Ordinary `can_use_tool` approval is not this barrier. Do not execute an effect in a live hook or settle the pending call with a denial to simulate suspension.
2. The supervisor requests completion of the deferred SDK exchange and closes the CLI. Its authenticated inspection confirms that the exact native writer epoch and its admitted descendants stopped. Drain output and close writers before capture. The trusted capture service remains running and compute stays allocated. Interruption acknowledgment, watcher completion or timeout alone is insufficient. Failure to stop leaves the epoch unaccepted and prohibits effects or another writer epoch. Provider terminal evidence is separately mandatory if replacing compute.
3. The capture adapter validates the deferred transcript and native graph, captures session files, workspace and required sidecars, and uploads their immutable encrypted objects. The Session accepts the matching pending epoch only after every required object is durably acknowledged. It checks the expected previous accepted head. A late publication cannot replace a newer accepted head.
4. The protected Entity validates the accepted pending reference, original call binding and executor admission. It records intent and schedules its existing governed effect adapter once. The effect Activity uses `maximum_attempts=1` for nonrepeatable actions and finite admitted deadlines. Activity reset/retry and direct executor entry are denied by the protected service policy. Receiver-side one-shot admission independently refuses a second invocation even if a control-plane task is redelivered. Repeated client requests retrieve the same intent/status/outcome; they do not receive a reusable spawn permit.
5. The inside effect adapter runs only the admitted typed operation against the exact accepted preimage while native writers remain stopped. It confines generated commands separately from its privileged recorder. After the invocation and all its workspace writers terminate, the trusted recorder validates and captures the exact outcome and postimage through the durable publication path. A local durable receipt is recoverable only if the selected failure profile preserves its bytes; it is not host-loss durability. The Entity marks completion only against acknowledged immutable outcome/postimage bytes. Loss of an Activity completion reply retrieves that record rather than executing again. If compute dies, only a controller admitted replacement with verified accepted state may run a later executor; an uncertain old effect is never dispatched there.
6. Restore and result insertion happen before any new CLI or model request, using the procedure below. The native engine never executes the externally completed call again.

An accepted intent without a definitive durable outcome is `UNCERTAIN` unless affirmative independent evidence proves nonexecution. The conservative default is to park. No next model segment, replacement tool identity or cleanup that destroys required evidence is permitted. Separately authorized containment does not manufacture an outcome. This contract preserves the pending owner decision concerning uncertain Bash disposition.

## Per-tool result projection

Projection is a finite typed adapter registry, keyed by exact capability profile and native tool name/schema. It is not a generic conversion of arbitrary JSON into a native tool result. Admit a tool only when both execution and native projection contracts are specified.

Each admitted entry contains an immutable golden native fixture captured on the exact CLI/profile, the tool's validated input schema, complete output/error schema, allowed transcript-carrier fields, model-visible rendering, metadata/sidecar relationships and workspace postconditions. The fixture is a schema/template, never an outcome. Actual execution supplies the values. Preserve original call ID, agent attribution, order and exact typed values; distinguish absent, null, empty, false and numeric values. Refuse unknown fields or schema changes unless explicitly admitted by that entry.

For native `Write`/`Edit`, specify file bytes, path validation, encoding, replacement/precondition rules and exact reported errors; the adapter publishes the resulting workspace and required native file-history metadata. For `Bash`, specify the admitted command envelope, stdout/stderr bytes and truncation, exit/interruption status, process lifetime and native output carrier. A timeout or missing process is not a definitive Bash result. `AskUserQuestion` uses the approved authenticated answer record and exact native answer representation. Read-only tools remain native under the admitted confinement policy. This list defines required contracts, not evidence that those adapters already exist.

Validate fixture fidelity in both directions: the adapter's produced native row must match the exact CLI's result schema, and resumed native execution must consume it as the original result without another physical tool invocation or missing-result substitution. Check raw native metadata, model-visible blocks and files independently. Tool projection remains unadmitted until these checks pass. An MCP tool result fixture cannot qualify native Bash/Edit/Write or child carrier semantics.

## Prelaunch restoration algorithm

`prepare_resume` executes inside the trusted content boundary while no CLI, tool, file writer or model request for the job is active:

1. Resolve only the Session's accepted epoch and selected authoritative outcomes. Verify authentication, all byte digests, package/policy/profile identities, exact workspace and graph membership. Verify that the prior native writer and effect writer scopes are stopped and current generation is admitted. For compute replacement, additionally verify independent controller evidence of the old compute incarnation's termination. Missing authority parks; never create an empty replacement Entity.
2. Parse every admitted transcript chain without discarding opaque records. Reject conflicting UUIDs, missing parents, cycles, malformed native call IDs and unexplained results. Bind each unresolved call to the exact `CallIdentity`; forbid remapping by tool name, latest result or array position alone.
3. Fetch the Entity outcome for each required original call. `UNCERTAIN`, missing required result/postimage or contradictory identity stops the entire affected recovery component. No callback dispatches a new effect. An already present exact result is a no-op; a conflicting result refuses.
4. Render native result rows only through the admitted per-tool registry. Preserve original agent, call and parent relationships. Derive append identities deterministically from the accepted source head and exact result bytes; publication retries must reuse identical row bytes, including timestamps. Do not regenerate a fresh timestamp under an existing append identity.
5. Construct immutable candidate transcript objects against the exact expected heads. A conditional append either retains exactly those bytes or reports a conflict. On a lost reply, read back the original append identity/head and compare complete bytes. Never blindly append a second result. Validate no required pending call remains unexplained.
6. Publish the complete candidate graph, transcript, workspace and sidecar manifests before a conditional Session-head transition from the source epoch to this `ResumeManifest`. Multi-file publication is not an atomic cross-service transaction: unaccepted immutable candidates remain unreachable. Reconciliation distinguishes candidate upload, head acceptance and materialization.
7. Materialize only the accepted resume manifest into a fresh native writer epoch in the current admitted compute generation, with the same native session and admitted paths. A controller approved compute replacement has a new generation; same compute continuation does not allocate another resource. Validate all bytes again. Start the ordinary local SDK/CLI using native `resume`, with the same profile and trusted hooks. No experimental SDK option is assumed. Startup refuses if the accepted graph requires a native resume capability that this exact profile lacks.

The experimental main-agent algorithm is precedent for steps 2 through 5, not proof of the complete application composition or current CLI compatibility. Extending it is project adapter engineering with explicit format ownership. Do not overwrite the retained SDK package, depend on an undisclosed private method or silently promote the experimental wheel.

## Parallel batches and child graph extension

The final service retains its positive parallel and child recovery obligations. Serial admission and unsupported-case refusal are a bounded first profile, not fulfillment or retirement of those obligations.

For batches, persist the original assistant-message batch identity, ordered per-call identities, independently recorded intent/outcome states and their shared workspace dependency relation. Complete independent outcomes may be fetched concurrently; transcript assembly preserves original association and order. Reuse completed results after a partial failure. A call affirmatively recorded by independent authority as never dispatched may receive its first dispatch under its existing original identity and intent, after its dependencies and accepted preimage are verified. No new model call or replacement tool identity is needed. If an earlier call changed the workspace, accept its exact postimage and the updated pending batch before dispatching the dependent original call. Missing authority or an uncertain dispatch never supplies this affirmative evidence and stays parked. Serialize conflicting workspace operations under the admitted conflict policy; reject an unsupported conflict before dispatch. Accept a resulting graph/workspace only when every required outcome and postimage is compatible. A sequential external executor can preserve parallel native call identity, but it is not evidence of supported concurrent effects.

For children, the proposed graph adapter records each agent's exact native transcript and sidecars, parent tool-use linkage, launch/completion state, nested pending calls and outcome dependencies. SDK 0.2.163 hook attribution supplies `agent_id` for child tool lifecycle events, but attribution does not itself establish child resumability. No parent result is synthesized from child text. A completed child uses its actual native completion carrier and exact retained graph; an active child requires an admitted native child-resume operation or a separately specified native completion projection. The experimental main-agent builder supplies neither.

The graph capability entry must identify the actual pinned native mechanism that consumes restored active-child state and binds the original parent call. Until that mechanism is identified and its input/output contract is verified, active-child recovery is **not admitted** and remains an explicit native capability gap. Do not invent `resume_child`, treat a new child as the old child, discard sidechains, or report child denial as positive recovery. Stopped captures after a complete native child tree can qualify completed-tree restoration separately. Mid-child crashes park with retained identities and evidence; they do not close the positive recovery requirement.

The current [official subagent continuation guide](https://code.claude.com/docs/en/agent-sdk/subagents#resume-subagents) describes resuming the parent session and asking the model to continue an agent by ID. This establishes a continuation feature, not exact restoration of an interrupted parent tool call. It does not by itself close this capability gap, and current documentation is not proof of behavior on the pinned SDK/CLI.

All graph writers and descendant processes participate in the stopped-epoch barrier. Depth/count, payload and workspace limits are profile inputs. Child or batch identities survive reset and Continue-As-New in protected authority; outer history rewind cannot remove an effect intent or select a different pending call at an existing ordinal.

## Crash disposition and acceptance

| Crash window | Required disposition |
|---|---|
| Before pending epoch acceptance | No governed dispatch. Retain prior accepted state and classify any observed unaccepted output. |
| After acceptance, before Entity intent | Reconcile the same accepted call and original intent identity. |
| After intent, before definitive outcome publication | Inspect exact independent authority; affirmative nonexecution requires evidence. Otherwise park without dispatch. |
| After durable outcome, before result insertion | Retrieve exact outcome/postimage and prepare resume; zero further effects. |
| During append or graph publication | Reconcile immutable bytes and expected heads; unreachable candidates are not accepted state. |
| After Session acceptance, before CLI startup | Materialize that exact accepted resume manifest under current generation admission. |
| During resumed CLI execution | Stop/fence old ownership before another generation; recapture or park according to the actual last accepted epoch. Never infer durable progress from observed stdout. |

AC-05/06/07/11 require concrete original-ID, exact native result/error/carrier, postimage, duplicate-dispatch, lost-reply, stale-generation and conflicting-head oracles. Include original host/disk removal, not just a Worker retry. The primary stopped-epoch profile must first prove one admitted native tool; positive batches and children require their own original-graph and partial-completion cases. Removing the prelaunch guard, changing a result ID, suppressing a required sidecar or enabling a second dispatch must make a paired negative control fail.

This is a proposed implementable main-agent protocol with explicitly named graph/projection extensions and native capability limits. It does not turn unimplemented child resume, arbitrary native tool fidelity or a local test into established support. Final confidentiality, disclosure, paid execution and uncertain-action owner decisions retain their governing gates.
